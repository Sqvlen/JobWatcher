# Джерело DOU (RSS)

Адаптер: `src/JobWatcher/Sources/DouRssSource.cs`. Читає публічну RSS-стрічку вакансій категорії .NET на jobs.dou.ua.

## Стрічка

- URL: `https://jobs.dou.ua/vacancies/feeds/?category=.NET` (налаштування `JobWatcher:Sources:Dou:FeedUrl`, змінна середовища `JobWatcher__Sources__Dou__FeedUrl`).
- Знайдено так: сторінка https://jobs.dou.ua/vacancies/?category=.NET має кнопку «RSS» (`<a class="rss" href="https://jobs.dou.ua/vacancies/feeds/?category=.NET">`) поруч із заголовком «N вакансій в категорії .NET». Для іншої категорії змінюється лише `category=`.
- Відповідь: `200`, `Content-Type: application/rss+xml; charset=utf-8`, `Cache-Control: max-age=600`, ~140 КБ, 25 найновіших вакансій категорії. Працює без авторизації і без спеціального User-Agent.

## Висновок

Явної згоди DOU на автоматичне читання стрічки **немає**. П. 2.5 забороняє автоматизований доступ до сайту, зокрема автоматичне збирання інформації, «без згоди Адміністрації»; про RSS-стрічки Правила не кажуть нічого. Тож читання **самої стрічки** умовами прямо не дозволене: згоду Адміністрації ми лише **виводимо** з того, що DOU сама виставляє цю стрічку для машинного читання. Це судження автора за непрямими ознаками, а не дозвіл і не юридична консультація:

- П. 2.5 забороняє автоматизований доступ «без згоди Адміністрації», а не будь-який автоматизований доступ. Ознаки того, що стрічку DOU виставляє для машинного читання: кнопка «RSS» є в інтерфейсі кожної сторінки вакансій, відповідь має тип `application/rss+xml` та заголовок кешування для клієнтів, які опитують стрічку (`Cache-Control: max-age=600`), а посилання в ній несуть мітку `utm_source=jobsrss`, за якою DOU відстежує перехід зі стрічки. RSS-рідер за своєю природою є автоматизованою програмою, і стрічка, судячи з усього, існує саме для нього. Але публікація стрічки не є висловленою згодою, а Правила її не згадують.
- Згоди на збирання HTML-сторінок це **не** дає. Адаптер читає лише стрічку; жодних інших адрес jobs.dou.ua не запитує, сторінок не парсить.
- Використання особисте й некомерційне (одна людина, сповіщення в її власний Telegram), що відповідає CC BY-NC-SA.

Якщо DOU заперечуватиме проти такого читання, вимкніть джерело: `JobWatcher__Sources__Dou__Enabled=false` (або зареєструйте `DisabledSource` замість адаптера). Якщо потрібна справжня згода, а не висновок із поведінки сайту, напишіть Адміністрації: https://dou.ua/contacts/.

## Ввічливість (що робить адаптер і чого не варто змінювати)

- Один запит `GET` на цикл опитування, без повторів і без паралельних запитів.
- `User-Agent: JobWatcher/1.0 (personal job alerts; reads the public DOU RSS feed)`: бот називає себе.
- Інтервал опитування: не частіше ніж раз на 10 хвилин. Стрічка кешується на 10 хвилин (`max-age=600`), тож частіші запити нових даних не дають. Типове значення `PollIntervalMinutes` = 15. Поки увімкнено DOU або Djinni, валідатор не пропускає значення менше 10 (`WatcherOptionsValidator`); нижче за 10, до мінімуму в 1 хвилину, інтервал допускається лише з вимкненими обома стрічками (DOU і Djinni).
- Посилання на вакансії лишаються такими, як у стрічці (з `?utm_source=jobsrss`): це і є вказання джерела для DOU. У кожному сповіщенні посилання веде на оригінальну вакансію на DOU.
- DTD у відповіді відхиляється (`DtdProcessing.Prohibit`), відповідь читається потоком.

## Формат стрічки (RSS 2.0)

Елемент `<item>` має лише `title`, `link`, `description`, `pubDate`, `guid`. Окремих полів компанії, зарплати чи міста **немає**: усе це в заголовку.

```
{назва вакансії} в {компанія}[, {зарплата}][, {місце}, {місце}, ...]
```

Приклади з реальної стрічки:

```
Backend .NET Developer в FREITTY, віддалено
Full Stack .NET Developer (Middle/Senior) в Teambase, $2500–4000, віддалено
Middle Back-end Developer в Personalities, HR Company, Львів
Lead Backend Engineer в DraftKings, Inc., Remote Ukraine
Senior Full-Stack (React &amp; C#) в A-listware, за кордоном, віддалено
```

Як адаптер це розбирає:

| Поле `Vacancy` | Звідки |
|---|---|
| `Source` (у `Vacancy` і `IVacancySource`) | `VacancySource.Dou` (= 1, назва в повідомленні «DOU») |
| `SourceId` | номер вакансії з `<link>` (`.../vacancies/366693/...` дає `366693`). `<guid>` **не** підходить: він закінчується міткою часу (`...?1792600064`), що змінюється, коли роботодавець оновлює вакансію |
| `Title`, `Company` | текст заголовка до останнього « в » і після нього до першої коми. Назва компанії може містити коми («Personalities, HR Company»): тоді вона збирається за слагом компанії з посилання (`/companies/personalitieshr-company/`), а юридична форма після коми («Inc.», «Ltd», «LLC») належить компанії. Заголовок у стрічці екранований як HTML двічі (`&amp;amp;`), тому декодується ще раз |
| `Url` | `<link>` без змін |
| `Salary` | елемент заголовка з цифрою і валютою (`$2500–4000`, `до $3500`, `від $1200`); `null`, якщо стрічка зарплати не вказує |
| `Location` | решта місць як у стрічці («Київ, Львів», «за кордоном», «Poland (remote)»), без «віддалено» і «Remote …»; `null`, якщо місць немає |
| `WorkMode` | `Remote`, якщо є «віддалено», «Remote …» або «… (remote)»; інакше `Office`, якщо є місто; інакше `Unknown` |
| `RemoteRestrictedTo` | рівно одна згадана область зі списку Ukraine / Europe / EU / US / UK (напр. «Remote Ukraine» дає `Ukraine`); завершальне «only» / «лише» / «тільки» перед пошуком відкидається, тож «Remote EU only» дає `EU`, а «Remote US only» дає `US` (і фільтр відкине таку вакансію); у всіх інших випадках `null` (кілька областей, країна не зі списку, область не названо): DOU є українським майданчиком, тож для нього `null` типове значення |
| `IsJunior` | у назві вакансії (не в компанії й не в описі) є junior / jr / trainee / intern / internship / джуніор / джун / стажер / стажист / стажування як окреме слово |
| `MinYearsExperience` | `ExperienceParser` лише по назві й по пунктах вимог, які знаходить `RequirementsExtractor`; не по всьому опису («2 year old startup» не стає двома роками) |
| `Description` | HTML опису як у стрічці |

Збої: помилка HTTP, нечитабельний XML, документ, що не є RSS, або стрічка з елементами, жодного з яких не вдалося розібрати, дають виняток (його рахує `SourceHealth`). Порожня, але коректна стрічка дає порожній список.
