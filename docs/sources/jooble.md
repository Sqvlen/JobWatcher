# Джерело Jooble (REST API)

Адаптер: `src/JobWatcher/Sources/JoobleSource.cs`. Шукає вакансії через офіційний REST API Jooble: два запити на цикл опитування (перше місто профілю і `remote`), перша сторінка кожного, результати зливаються без дублів за `id` вакансії.

> **УВАГА: ЗРАЗОК ДЛЯ ТЕСТІВ СИНТЕТИЧНИЙ.** `tests/JobWatcher.Tests/Fixtures/jooble-response.json` не є справжньою відповіддю Jooble. Ключа API на момент написання не було (його видають лише за заявкою замовника), тому файл складено вручну за назвами полів з офіційної документації; вакансії, компанії й `id` вигадані. Тести доводять, що адаптер читає **задокументований** формат, але не те, що справжні відповіді виглядають саме так. Перевірка зі справжнім ключем лишається відкритою: див. «Перевірка з реальним ключем» нижче.

## Ключ API

- **Типово Jooble вимкнено** (`Sources:Jooble:Enabled = false` у `appsettings.json`): ключ видає лише користувач, а квота ключа обмежена, тож застосунок працює з коробки лише на DOU. Щоб увімкнути Jooble, задайте `JobWatcher__Sources__Jooble__Enabled=true` разом із `JobWatcher__Sources__Jooble__ApiKey=<ключ>`.
- Ключ видає Jooble за заявкою: форма на https://jooble.org/api/about (ім'я, посада, email, сайт, телефон). Безкоштовний. Ключ для України береться на https://ua.jooble.org/api/about (див. нижче).
- Ключ кладеться у змінну середовища `JobWatcher__Sources__Jooble__ApiKey`. Без ключа адаптер кидає `SourceNotConnectedException` ще до будь-якого запиту (і незалежно від інтервалу між вибірками: запитів немає, квота не витрачається), користувач отримує одне повідомлення «джерело не підключено», а валідатор налаштувань не пропускає `Enabled=true` без ключа.
- **Ключ діє лише на тому домені Jooble, де його видано.** Довідка Jooble (див. нижче): ключ з jooble.org дає доступ «виключно до вакансій США»; для інших країн треба окремий ключ на регіональному домені (`uk.jooble.org/api/about`, `de.jooble.org/api/about`, для України `ua.jooble.org/api/about`).
- **Адреса API налаштовується: `JobWatcher__Sources__Jooble__BaseUrl`** (поле `JoobleOptions.BaseUrl`, типове значення `https://jooble.org/api`; ключ додається до нього останнім сегментом шляху: `{BaseUrl}/{key}`). Профіль шукає Київ і віддалену роботу, тож український ключ береться на `ua.jooble.org/api/about`, і, **імовірно**, потрібно задати `JobWatcher__Sources__Jooble__BaseUrl=https://ua.jooble.org/api` (**імовірно: перевірте зі справжнім ключем**; у прикладі відповіді з документації посилання теж `https://ua.jooble.org/jdp/...`, зарплата в UAH, місто Kyiv, але що саме приймає кожен домен, без ключа перевірити не можна). Валідатор вимагає, щоб `BaseUrl` був абсолютним `https`-адресою (ключ іде у шляху URL, тож `http` не допускається) без рядка запиту й фрагмента (`?`, `#`): ключ дописується в кінець шляху, і після `?` чи `#` він опинився б не там. Якщо ключ не підійде до домену, Jooble відповість 403, і адаптер скаже про це у виключенні («ключ недійсний або виданий для іншого домену Jooble»).

## Запит і відповідь (як задокументовано)

Джерело: Jooble Help Center, «Jooble REST API Documentation» (https://help.jooble.org/en/support/solutions/articles/60001448238) і «How to connect to the Jooble REST API» (https://help.jooble.org/en/support/solutions/articles/60000922689-how-to-connect-to-the-jooble-rest-api). Обидві сторінки прочитано напряму 2026-10-22 (позначка «Modified on: 16 Aug, 2026»).

```
POST https://jooble.org/api/{api_Key}
Content-Type: application/json

{ "keywords": "Sales Manager, Administrator", "location": "Kyiv", "radius": "80", "page": "1", "companysearch": "false" }
```

Ключ іде **в шляху URL**. Параметри тіла:

| Поле | Тип | Обов'язкове | Зміст |
|---|---|---|---|
| `keywords` | string | так | ключові слова або назви посад |
| `location` | string | так | «Location name (city, region, or country)» |
| `radius` | string | ні | радіус, км: 0, 4, 8, 16, 26, 40, 80 |
| `salary` | integer | ні | мінімальна зарплата |
| `page` | integer | ні | сторінка, за замовчуванням 1 |
| `ResultOnPage` | integer | ні | вакансій на сторінці |
| `SearchMode` | integer | ні | режим пошуку, за замовчуванням 0 |
| `companysearch` | boolean | ні | `true`: шукати слова в назвах компаній, `false`: у назвах і описах |

Відповідь `200`:

```json
{ "totalCount": 1,
  "jobs": [ { "id": 1234567890, "title": "Sales Manager", "location": "Kyiv", "snippet": "This is a great opportunity to join our team...",
              "salary": "17,600 UAH", "source": "jooble", "type": "Full-time", "link": "https://ua.jooble.org/jdp/12345",
              "company": "ABC Corp", "updated": "2023-09-15T12:55:35.3870000" } ] }
```

| Поле відповіді | Тип | Зміст за документацією |
|---|---|---|
| `totalCount` | integer | скільки всього вакансій знайдено |
| `jobs[].id` | integer | унікальний ідентифікатор вакансії |
| `jobs[].title` | string | назва |
| `jobs[].location` | string | місце |
| `jobs[].snippet` | string | короткий уривок опису |
| `jobs[].salary` | string | діапазон у вигляді `{min} - {max} {currency}` |
| `jobs[].source` | string | звідки вакансія |
| `jobs[].type` | string | тип зайнятості («Full-time», «Part-time») |
| `jobs[].link` | string | пряме посилання на вакансію на Jooble |
| `jobs[].company` | string | компанія |
| `jobs[].updated` | string | ISO-час останнього оновлення |

Коди: `200` успіх; `403 Access Denied`: недійсний або відсутній ключ; `404`: немає такого ресурсу. Інших полів, помилок у тілі відповіді та поведінки при вичерпаному ліміті документація не описує.

## Ліміти: ВАЖЛИВО

Документація Jooble (Help Center, як я її прочитав): «The free REST API plan includes a total lifetime limit of 500 requests per key (this is an absolute lifetime quota, not a monthly limit).» Тобто 500 запитів **за весь час життя ключа**, а не на місяць.

Одна вибірка адаптера це 2 запити, тож безкоштовного ключа вистачає на 250 вибірок. Щоб квота не вичерпалася за кілька днів, адаптер сам обмежує частоту справжніх вибірок:

- `JobWatcher__Sources__Jooble__MinFetchIntervalMinutes` (`JoobleOptions.MinFetchIntervalMinutes`), **типове значення 720 (12 годин)**; валідатор вимагає ≥ 1, коли Jooble увімкнено.
- Адаптер пам'ятає в пам'яті момент початку останньої справжньої вибірки (момент, коли почав робити HTTP-запити, **також коли вони завершилися помилкою**: невдалий запит теж міг зарахуватися в квоту) і її результат. Якщо `FetchAsync` викликають раніше, ніж минув інтервал, жодного HTTP-запиту не робиться, а результат залежить від того, **чим закінчилася остання справжня вибірка**:
  - **вдало**: повертається порожній список, а в журнал пишеться один рядок рівня Information `Jooble: no request this time, the next one is due after 2026-10-22T20:00:00.0000000Z (MinFetchIntervalMinutes=720)`: це UTC-час, раніше за який нового справжнього запиту не буде (рядок без ключа й адрес; після невдалої вибірки його немає, бо виняток нижче вже називає цей час);
  - **невдало**: кидається **новий** виняток `InvalidOperationException` (не збережений об'єкт, без `InnerException`) з текстом «The last Jooble fetch failed: {той самий очищений текст помилки, що був у першому винятку}. No new request is made before {UTC-час наступної спроби, ISO-8601, напр. 2026-10-22T20:00:00Z}, to protect the request quota of the API key.». Текст складається в адаптері і не містить ні URL, ні ключа (для винятків не з нашого коду зберігається лише назва типу). Час наступної спроби це початок тієї вибірки плюс інтервал.
  - Наступна справжня вибірка після інтервалу працює як зазвичай і замінює запам'ятований результат (успіх або невдачу).
  Інтервал відлічується від початку вибірки, а не від кінця; годинник монотонний (`TimeProvider`, у тестах підставний).
- Відсутній ключ перевіряється раніше і кидає `SourceNotConnectedException` одразу, не чіпаючи інтервал.
- Стан лише в пам'яті: перезапуск процесу дає нову вибірку одразу. Часті перезапуски витрачають квоту.
- `PollIntervalMinutes` (типово 15 хв) для Jooble більше не визначає витрату квоти: цикли всередині інтервалу не роблять запитів до Jooble (порожній результат після вдалої вибірки, повторена помилка після невдалої), а DOU опитується як зазвичай.

Скільки триватиме ключ при різних `MinFetchIntervalMinutes` (2 запити на вибірку, 250 вибірок):

| `MinFetchIntervalMinutes` | Ключ вичерпається приблизно через |
|---|---|
| 60 | 10,4 доби |
| 360 (6 годин) | 62 доби |
| 720 (12 годин, типове) | 125 діб |
| 1440 (раз на добу) | 250 діб |

Що буде після вичерпання, документація не каже (найімовірніше 403). Це буде звичайна помилка вибірки (виключення), і вона **не губиться за інтервалом**: `WatchCycle` бачить виключення при кожному циклі всередині інтервалу (адаптер повторює невдачу новим винятком, див. вище), тож лічильник невдач поспіль у `SourceHealth` росте щоцикла, і повідомлення про недоступність Jooble приходить після `FailureAlertThreshold` циклів (типово 3 цикли, тобто приблизно 45 хвилин), хоча HTTP-запитів у цей час немає. Коли наступна справжня вибірка після інтервалу вдається, цикли всередині нового інтервалу знову отримують порожній список, що рахується успіхом. Вищий ліміт можна домовитися з Jooble напряму; увімкнене джерело знову вимикається так: `JobWatcher__Sources__Jooble__Enabled=false`.

## Висновок

Умови **не забороняють** таке використання, але і не дозволяють його явно, тому це висновок за непрямими ознаками, а не юридична консультація:

- REST API є офіційним каналом машинного доступу, який Jooble видає за ключем безкоштовно; заборона на «automatic process» в Terms of Service стосується сайту, а не цього інтерфейсу.
- Використання особисте й некомерційне: одна людина, сповіщення у її власний Telegram, дані ніде не публікуються і не зберігаються, крім ідентифікаторів уже надісланих вакансій.
- Застереження 1: «Jooble API Terms of Use» не прочитано. Прочитайте їх, коли Jooble видасть ключ (зазвичай вони приходять разом із ним або на сторінці заявки), і перевірте, чи дозволяють вони особисте використання, скільки запитів дозволено і чи треба вказувати джерело.
- Застереження 2: API орієнтований на вебмайстрів, а форма просить «website». Опишіть проєкт у заявці чесно (особистий бот сповіщень про вакансії); якщо Jooble відмовить у ключі або заперечуватиме, не вмикайте джерело (воно типово вимкнене) або вимкніть його: `JobWatcher__Sources__Jooble__Enabled=false`.
- Застереження 3: ліміт ключа в 500 запитів за весь час (див. «Ліміти»; адаптер сам дозволяє справжню вибірку не частіше ніж раз на 12 годин).

## Ввічливість і безпека ключа

- Запити йдуть послідовно, без повторів і без паралельності; `User-Agent: JobWatcher/1.0 (personal job alerts; uses the Jooble REST API)`; сторінка не вказується (за замовчуванням перша), тож не більше двох запитів за вибірку і не частіше ніж раз на `MinFetchIntervalMinutes` (див. «Ліміти»).
- **Ключ у шляху URL, тож він не повинен потрапити ні в які повідомлення чи журнали.** Адаптер сам складає тексти виключень (`HttpRequestException` з кодом статусу або `HttpRequestError`, `InvalidDataException`) і не передає далі `InnerException`, бо виключення HTTP-стека можуть містити URL. Будь-яке інше виключення фреймворку (таймаут `HttpClient`, `IOException` тощо) замінюється на `HttpRequestException` «The Jooble request failed (unexpected {тип}).» без внутрішнього виключення; без змін проходить лише скасування самим викликачем (його `CancellationToken`). Це перевіряє тест `Exception_text_never_contains_api_key` (18 сценаріїв; усе, що «відповідає» підставний сервер, повторює адресу запиту, тож містить ключ). Прямі сценарії: відповіді HTTP 500, 403 і 404 (`http500`, `http403`, `http404`); помилка мережі (`network`); невалідний JSON (`invalid-json`); порожнє тіло (`empty-body`); не відповідь пошуку (`not-a-search-response`); жодної читабельної вакансії (`none-mappable`); збій другого запиту (`second-query-fails`); виключення фреймворку, які кидає сам обробник: `IOException` з внутрішнім виключенням (`handler-throws-other`) і `TaskCanceledException` з `TimeoutException` усередині, тобто таймаут (`handler-throws-timeout`). Ще сім сценаріїв `throttled-after:*` (`http500`, `http403`, `network`, `invalid-json`, `second-query-fails`, `handler-throws-other`, `handler-throws-timeout`) перевіряють виключення виклику всередині інтервалу після такої невдачі: це новий `InvalidOperationException` без жодного нового запиту. У всіх сценаріях `ToString()` і `Message` виключення (а значить, і всі внутрішні) не містять ключа, а `InnerException` порожній.
- **Реєстрація в DI (зроблено, Task 11).** Журнал `IHttpClientFactory` пише URL запиту разом із шляхом (перевірено експериментом на .NET 10: `Sending HTTP request POST https://jooble.org/api/<ключ>?*`, маскується лише рядок запиту `?...`, шлях ні). Тому в `ServiceCollectionExtensions` клієнт Jooble зареєстровано як `AddHttpClient<JoobleSource>(client => client.Timeout = HttpTimeout).RemoveAllLoggers()`: інакше ключ потрапляв би в журнал на кожному циклі. Там же задано таймаут `HttpClient` у 30 секунд (`HttpTimeout`). Те саме зроблено для клієнта Telegram, бо токен бота теж іде в URL.

## Як адаптер відображає відповідь на `Vacancy`

| Поле `Vacancy` | Звідки |
|---|---|
| `Source` (у `Vacancy` і `IVacancySource`) | `VacancySource.Jooble` (= 3, назва в повідомленні «Jooble») |
| `SourceId` | `id` вакансії текстом цифр, як прислав API (числа 64-бітні й можуть бути від'ємними, тому беруться з «сирого» JSON, а не через `int`); рядковий `id` теж приймається. Якщо `id` немає, береться стабільний хеш посилання: `link-` + перші 16 hex-цифр SHA-256 від `link` (не `GetHashCode`, що змінюється між запусками), тож та сама вакансія завжди має той самий id |
| `Title`, `Company`, `Url` | `title`, `company` (немає або порожня дає видимий текст «не вказано», `Placeholders.NotSpecified`, той самий, що в Djinni: порожню компанію цикл перевірки відкинув би, і вакансія мовчки пропала б; рейтинг для «не вказано» не шукається), `link` без змін |
| `Salary` | рядок `salary` як є (обрізано лише пробіли по краях); `null`, якщо порожній чи відсутній; нічого не вигадується |
| `Location` | `location`; `null`, якщо порожнє чи відсутнє |
| `Description` | `snippet` як є, з HTML-розміткою (`<b>`, `&nbsp;`); `null`, якщо порожній |
| `WorkMode` | `Remote`, якщо `type`, `location` або `title` містять слово як окреме слово (без урахування регістру): remote / remotely / віддален* / дистанційн*. Уривок опису не враховується (там пишуть і «remote працювати не можна»). Інакше `Office`, якщо є `location`; інакше `Unknown` |
| `RemoteRestrictedTo` | лише для `Remote` (таблиця назв областей і правило «junior» спільні для всіх адаптерів: `Sources/SourceMapping.cs`): `location` ділиться за «, ; / \| ( )» і « - », слова remote видаляються, і якщо рівно одна з частин є відомою областю (Ukraine / Europe / EU / US / UK та їхні назви: «Україна», «Європа», «USA», «United States»…), повертається саме вона; інакше `null` (не обмежено, невідомо, декілька областей, країна не зі списку). Завершальне «only» / «лише» / «тільки» перед пошуком відкидається, тож «Remote EU only» дає «EU», а «Remote US only» дає «US» (і фільтр відкине таку вакансію). Фільтр порівнює рядок на рівність, вільного тексту тут не буває |
| `IsJunior` | у `title` є junior / jr / trainee / intern / internship / джуніор / джун / стажер / стажист / стажування як окреме слово |
| `MinYearsExperience` | `ExperienceParser` лише по `title` і по пунктах вимог, які знаходить `RequirementsExtractor` у `snippet`; не по всьому уривку. Jooble дає лише уривок, тож список вимог зазвичай порожній, і це припустимо |

Вакансія без `title` або без `link` з адресою `http(s)` пропускається. Збої, що видно через `SourceHealth` (виключення): помилка HTTP; мережева помилка; відповідь, що не є JSON; JSON без масиву `jobs`; відповідь, у якій `jobs` непорожній, але жодної вакансії не вдалося прочитати. Порожній `jobs: []` це коректний порожній результат. Виклик усередині `MinFetchIntervalMinutes` після попередньої вибірки не робить запитів: після вдалої вибірки він дає порожній список, після невдалої кидає виняток із текстом останньої помилки та часом наступної спроби (див. «Ліміти»). Якщо другий запит упав, виключення летить, а вже отримані вакансії першого запиту не повертаються: частковий результат приховав би збій.

## Перевірка з реальним ключем (відкрита, робить користувач)

Коли ключ буде, один раз перевірте і за потреби виправте адаптер та зразок (замініть синтетичний файл справжньою відповіддю, прибравши ключ із усього, що зберігаєте):

1. Який домен і яка адреса приймають ключ (`jooble.org` чи `ua.jooble.org`): чи справді для українського ключа потрібен `JobWatcher__Sources__Jooble__BaseUrl=https://ua.jooble.org/api` (див. «Ключ API»).
2. Чи дає `location: "remote"` віддалені вакансії. Документація описує `location` як місто, регіон чи країну; значення `remote` у ній не згадане, тож воно може не працювати як «віддалено» (тоді запит варто замінити, наприклад, на слово remote в `keywords` разом із країною).
3. Чи `id` справді число (і чи вміщається воно в 64 біти), чи є вакансії без `id`.
4. Формат `salary` у справжніх відповідях (валюта, період, «від», «до», `грн.`) і чи `SalaryParser` їх читає.
5. Чи є HTML-розмітка або сутності (`<b>`, `&nbsp;`, `&amp;`) у `title`, `company`, `location` (адаптер залишає їх як є) і чи є у `snippet` списки для вимог.
6. Як виглядає відповідь при неправильному ключі (403) і при вичерпаному ліміті.
7. Текст «Jooble API Terms of Use» (див. «Висновок»).

## Повного опису й вимог немає (перевірено 2026-10-23)

API віддає лише `snippet`, «короткий уривок опису» (довжину документація не називає), тож блоку `📋 Вимоги:` для Jooble зазвичай немає. Повний текст є лише на сторінці вакансії `ua.jooble.org/desc/...`, і читати її, як Djinni, **не можна**:

- `ua.jooble.org/robots.txt` для всіх роботів (`User-agent: *`) закриває `/desc/` і будь-які адреси з `?ckey=` (посилання, які копіюють із сайту, мають саме такий параметр); `jooble.org/robots.txt` теж закриває `/desc/`.
- Сторінка відповідає на звичайний запит `HTTP 403` із заголовком `cf-mitigated: challenge` (перевірка Cloudflare «Just a moment…»); сторінки документації `jooble.org/api/about` і `ua.jooble.org/api/about` відповідають так само. Прочитати її означало б проходити перевірку на бота, чого проєкт не робить.

Законний шлях до вимог для таких вакансій один: знайти ту саму вакансію в іншому джерелі з повним текстом (DOU, Djinni, JobsPipe). Для цього потрібна дедуплікація між джерелами, якої поки немає. Повний текст отримує [JobsPipe](jobspipe.md).
